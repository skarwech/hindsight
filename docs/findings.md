### Adversarial review of F1

Seven read-only skeptics each tried to refute one F1 result with their own queries. Verdicts: six "weakened" (the result held, but the check proved less than it claimed) and one "refuted" (T3: the original 2,000-row stress test missed the failure). Every issue they raised was fixed in `eval/f1_check.py` / `eval/f1_vectors.py` or is recorded above:

- missing files and unverified reference files no longer pass F1.1b; the sums files are tied to the release digests;
- F1.2 compares the loaded vector bytes against the release and asserts the 290 truncated;
- F1.3 diffs every table row and the miss list, adds the exact-search oracle, and records the DB target;
- pitfalls gate on error codes and row counts, and add the `KEEP`, existing-column `MODIFY`, `secure_timestamp` and connector bare-date cases;
- T3 runs at 20k rows with churn and backdated rows, and keeps the review's raw evidence;
- T4 isolates each routing leg, checks the period columns, and compares with an independent oracle at every boundary;
- T5 removes the 512-token truncation artefact and adds parity with S's stored vectors.
